# miauDit local core (first slice)

Offline implementation of the CLI core described in `docs/cli-and-normalized-api.md`. Rust, unix only.

- `miaudit-schema`: versioned types, strict closed-schema input validation, canonical serialization (`auditai-c14n-v1`), domain-separated SHA-256 IDs, tree digests and diffs.
- `miaudit-cli` (binary `miaudit`): `init`, `status`, `add`, `diff [--staged]`, `context|decision|evidence add --file`, `gaps`, `commit -m`, `log`, `show`, `verify`, `push`, Git linking (`bind`, `bind-pending`, `git-hook install`, `bindings`, `related`) and hook capture (`capture`, `stop-check`, `events`). Every command accepts `--json` (versioned envelope `contract_version: "1"`).
- `miaudit-ui` (library): the read-only viewer, started with `miaudit ui` (default `ui` feature of `miaudit-cli`). See below.
- `miaudit-web` and `web/`: the React + TypeScript interface (Vite) shared by the viewer and the team server, embedded into the Rust binaries by `miaudit-web`. See Web interface below.
- `miaudit-server` (binary `miaudit-server`): team server with a GitHub-style UI over MongoDB. See below.

Exit codes: `0` ok, `1` internal, `2` validation/integrity failure, `3` conflict, `4` insufficient evidence (partial verification).

## Linking audit commits to Git/GitHub commits
`miaudit bind <audit-id> --git-commit <rev>` compares the audit commit's changes with the Git commit's tree (same content and mode; deletions must be absent) and stores a **separate, immutable attestation** (`.miaudit/bindings/`), so the audit ID never changes. Result: `full`, `partial`, or `asserted` (only with `--assert`; a plain mismatch is rejected with `BINDING_MISMATCH`). Several audits may bind to one Git commit and vice versa.
`miaudit bind <audit-id> --pr <number|url>` links an audit to a pull request: `gh pr view` supplies the head commit, the same comparison runs against it (the head must be in the local repository), and the binding also records the PR number, URL, head commit and state. A PR binding is found through its head commit by `related`. `--git-commit` and `--pr` are mutually exclusive.
`miaudit related <git-rev>` answers "which audits explain this commit". The GitHub URL is derived from `origin` (credentials are never stored) and does **not** prove the commit was pushed.

## Tests
`cargo test --workspace` runs unit tests and integration suites that drive the real `miaudit` binary (including `miaudit ui`) (`tests/*.rs`). `scripts/e2e.sh` is an end-to-end run of the installed binaries in a temporary Git repo: hook payloads, audit commit, verify, tamper detection, post-commit binding and the viewer over HTTP. Building or linting is not evidence that tests ran.

## Project profile
`miaudit init` (or `miaudit project init`) creates `.miaudit/PROJECT.md`, a template of questions for the developer: run locally, run tests, staging, credentials (names only), how to collect frontend and API evidence, how to run the previous version, constraints. `miaudit project check` reports `missing`, `incomplete`, `complete` or `contains_secret` (exit 0, 4, 4, 2) and adds the gaps `PROJECT_PROFILE_MISSING`, `PROJECT_PROFILE_INCOMPLETE` and `PROJECT_PROFILE_SECRET` to `status` and to every audit commit. Secret detection is a heuristic (known token prefixes, AWS keys, JWTs, private keys, labelled values) and never echoes the value. `miaudit session-start` is the `SessionStart` hook: it prints a fixed reminder (the questions when the profile is not complete, otherwise a pointer to read it) and never the file content. Editing `.miaudit/PROJECT.md` through a tool is not flagged as tampering with the store.

## Evidence by kind of change
A context can declare `change_kind` (`frontend`, `api`, `other`) and evidence can declare `phase` (`before`, `after`) and `environment` (`local`, `staging`, `production`, `ci`). For `frontend`, `miaudit gaps` expects an image (checked by content, not extension) before and after; for `api`, the output of the old and new version run against the API, in `local`, `staging` or `production`. Missing pieces appear as `FRONTEND_EVIDENCE_MISSING:*` and `API_EVIDENCE_MISSING:*`; an undeclared kind is `CHANGE_KIND_UNDECLARED`. The viewer renders image evidence through a GET-only route that serves only blobs referenced by that audit whose digest matches and whose bytes are a PNG, JPEG, GIF or WebP (never SVG). Self-reported metadata: nothing proves which version produced a screenshot.

## Store and author
Each repository has a `.miaudit/` directory at its root (found by walking up, like `.git`) that ignores itself through `.miaudit/.gitignore`. Each audit commit records the GitHub user in `author`: `gh api user` login and id (`derived`), `MIAUDIT_GITHUB_USER` (`self_reported`), or `unavailable`. It is not signed.

## Why a capture capability is unavailable
`CAPTURE_UNAVAILABLE:<capability>` now says why, from what the audit commit saw: no hook events at all since the last audit commit (hooks not installed or not firing), the event log failed its integrity check, or events exist but none of the kind that capability needs (for example no shell commands for `command_execution_receipts`). Audit commits made before this wording keep the old text, because the gap is part of the manifest and its ID.

## Checkpoints and superseded decisions
Audit commits used to be written only when files were staged, so a turn made of commands (a deploy, a secret change, a failed rollout) or of a developer's answer left nothing but the raw hook log, and an earlier decision could go stale with no way to say so.
- **Automatic checkpoints.** `miaudit stop-check` (the `Stop` hook) records an audit commit at the end of a turn when hook events exist since the last audit commit, nothing is staged, no context, decision or evidence is pending, the event chain is intact, and no edited file is waiting to be audited. The checkpoint has no file changes, attaches the hash-only event receipts as its one evidence object, is described by counts (`checkpoint: 1 prompt, 1 assistant message digest, 2 commands since the last audit commit`), and carries the gap `AUTO_CHECKPOINT` plus the usual `NO_CONTEXT` and `NO_DECISION`. It never calls `gh` (the author is `MIAUDIT_GITHUB_USER` or `unavailable`) so the hook stays fast, and it never commits staged or pending work, so the agent's own audit is not pre-empted. Unaudited edits still block the first Stop and are never swallowed. A failure only prints a line to stderr.
- **Switching it off.** `miaudit checkpoints` shows the setting, `miaudit checkpoints off|on` stores it in `.miaudit/config.json`, and `MIAUDIT_CHECKPOINT=0` disables it for one run. Checkpoints grow the local store by one small audit per turn; the store is gitignored.
- **Follow-up audits without files.** `miaudit commit` already accepts an empty snapshot once any context, decision or evidence is pending, so the agent can record what a turn did and why (command output as evidence, a developer's decision) without staging anything.
- **Superseding a decision.** A decision may carry `"supersedes": ["dec_<id>", ...]` (up to 16, each must already be in the store, else `DECISION_REFERENCE_UNAVAILABLE`). The field is left out of the stored decision when empty, so existing decision ids do not change. The older audit is not touched; the viewer and the API mark the old decision `superseded_by` and link the audit that holds the new one, and the new decision lists what it supersedes. The server records this at ingest and backfills audits stored earlier when it starts.
- **Limits.** A checkpoint says that something happened, not what it meant or whether it worked; command output and credentials are not stored. Only a follow-up audit written by the agent (or developer) carries that, and nothing forces it except the instructions in `CLAUDE.md`.

## Hook capture
`miaudit init` creates `.miaudit/` and links the Claude Code hooks: the bundled `claude-code.settings.json` is merged into `.claude/settings.json` (`--local` for `settings.local.json`, `--no-hooks` to skip). Existing settings and other hooks are kept, commands already present are not duplicated, an unchanged file is not rewritten, and a settings file that is not a JSON object stops `init` before anything is created. The hooks call `$HOME/.cargo/bin/miaudit`; `init` warns when that binary is missing. Codex hooks are still copied by hand.

`miaudit capture` is the entry point for Claude Code and Codex hooks. Besides prompts, edits and commands (now with output digest and exit code), it records `Read`/`Grep`/`Glob`/`WebFetch`/`WebSearch`/MCP calls (paths, hosts, digests), subagent spawns and `SubagentStart`/`SubagentStop`, and `stop-check` records a digest of the last assistant message and of the transcript at each `Stop`. Everything is a hash, like Git objects: no output text, URL paths or reply text is stored. It reads the hook JSON on stdin and appends an `observed` event to `.miaudit/events.jsonl` (hash-chained, append-only, file-locked so parallel hooks are safe). It prints nothing to stdout (that would enter the model context) and exits 0 even on failure, which it records as a `capture_error` event. Only digests are stored for commands and file contents; the user prompt goes to an unencrypted blob. `miaudit stop-check` is the Stop hook: exit 2 with a stderr message once when edits were observed but not audited (it lets the agent stop when `stop_hook_active` is true). Example configurations: `miaudit-cli/hooks/claude-code.settings.json` and `miaudit-cli/hooks/codex.hooks.json`; nothing is installed automatically. `capture --agent codex` understands the Codex payload (`apply_patch` patch text is parsed for file paths; only paths and digests are stored, never the patch body). Codex needs the hook trusted in `/hooks` and the Codex payload shape was taken from its public documentation, not from a live run.
`miaudit commit` attaches the new events as one `observed` evidence object and advances `.miaudit/events.cursor`; `miaudit verify` re-checks the chain inside that evidence. Gaps compare events with the snapshot (see `CLAUDE.md`). The chain proves internal consistency only: the agent runs as the same user and could rewrite `.miaudit/` and recompute it, and `Bash` can change files that no edit event shows. Signing and a relay outside the agent's reach are not implemented.

## Web interface
`web/` is a Vite + React + TypeScript app (React Router, no UI framework). `miaudit-web` embeds its production build (`web/dist`) into the binary, so `miaudit` (with its `ui` feature) and `miaudit-server` stay single files. Both serve the same JSON API, which is what the app talks to and what `miaudit remote` reads: `GET /api/v1/config`, `GET /api/v1/repos[?q=]`, and under `/{owner}/{name}/api/`: `repo`, `audits[?page&author&gap]`, `audits/{id}` (raw manifest), `audits/{id}/detail`, `audits/{id}/evidence/{eid}/image`. Any other `GET` that is not an API path returns the app shell so client-side routes work on reload.
- Build: `cargo build` runs `npm ci` (when `web/node_modules` is missing) and `npm run build` when `web/dist` is older than its sources, so Node.js 20+ and npm are needed to build. Without Node the build embeds a placeholder page and warns; `MIAUDIT_SKIP_WEB_BUILD=1` skips the npm step. `web/dist` and `web/node_modules` are not committed.
- Develop: `cd web && npm run dev` serves the app with hot reload and proxies the API to `MIAUDIT_DEV_API` (default `http://127.0.0.1:7171`). `npm test` runs the Vitest and Testing Library suites; `npm run build` type-checks and builds.
- Security: the CSP is `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; frame-ancestors 'none'` (no inline script or style, no `unsafe-inline`). React renders every value from the API as text, the code never uses `dangerouslySetInnerHTML`, and only `https://github.com/...` URLs become links (with `rel="noopener noreferrer"`). The API returns untrusted text untouched and relies on the renderer for escaping; Vitest tests cover script payloads and non-GitHub URLs. With `MIAUDIT_SERVER_READ_PASSWORD` set, the app shell and the assets sit behind the same Basic password as the API.

## Viewer
`miaudit ui [--repo <path>] [--port 7070]` serves the web interface for one repository (the store is found by walking up from the current directory like every other command; `--port 0` picks a free port; with `--json` the first line is an envelope holding the `url`, then it serves until Ctrl-C): audit commits, their Git and PR links, context, decisions, evidence, gaps and a live `miaudit verify` result. GET only, `127.0.0.1` only, strict `Host` check against DNS rebinding. The viewer presents itself as one repository `local/<directory>` and `/` redirects to it. Verification runs this same executable (`miaudit verify`), found with the OS's current-executable lookup, so a bare `miaudit` is never used (on macOS it would resolve to the system tool). The old separate `miaudit-ui` binary no longer exists: remove a stale `~/.cargo/bin/miaudit-ui`. `cargo build -p miaudit-cli --no-default-features` gives a `miaudit` without the viewer (smaller, no Node needed; `miaudit ui` then reports `UI_NOT_BUILT`).

## Team server
`miaudit-server serve` hosts audit commits from many repositories in one MongoDB database. Pages (the React app): `/` (repository list with search), `/{owner}/{name}` (audit commits, authors, paging, author filter), `/{owner}/{name}/audit/{id}` (the same detail view as the local viewer, with integrity checks computed from what the server holds).
- Setup: `MIAUDIT_MONGO_URI` (default `mongodb://127.0.0.1:27017`) and `MIAUDIT_MONGO_DB` (default `miaudit`). `miaudit-server token create <name>` prints a push token once (only its SHA-256 is stored); `token list` and `token revoke <name>` manage them. `serve --bind --port` (default `127.0.0.1:7171`).
- Push: `MIAUDIT_SERVER=https://host MIAUDIT_TOKEN=... miaudit push [--name owner/name]`. The token is read from the environment only. The slug comes from the GitHub `origin` remote, otherwise `local/<directory>`; a slug can belong to one repository id only (conflict exits 3). Push is incremental and idempotent: the client asks which commits, objects, blobs and bindings the server lacks and sends only those (blobs, objects, commits, then bindings). Exit 4 if something referenced is missing locally.
- The server never trusts the client: every blob must hash to its digest, every context, decision and evidence object to its id, every manifest to its audit id and tree digest, every binding to its binding id, and a manifest must belong to the repository it is filed under. Mismatches are refused with 422. Objects are immutable; re-sending identical content is a no-op, different content under an existing id cannot happen because ids are hashes.
- Storage: collections `repos`, `audits`, `objects`, `blobs`, `bindings`, `tokens`, each keyed by repository id with unique indexes. Documents keep the exact JSON text received next to a few extracted fields used for listing, because verification needs the original bytes. Blobs are stored in the document (15 MB limit under MongoDB's 16 MB cap); GridFS is the way past that.
- Access: pushing needs a token. Reading has no user accounts yet: set `MIAUDIT_SERVER_READ_PASSWORD` for one shared HTTP Basic password; without it, anyone who can reach the port can read every audit, and the server warns when bound to a non-loopback address. Tokens are team-wide, not scoped to a repository. Serve it behind TLS: tokens and the password cross the network otherwise (`push` warns on plain http to a non-local host).
- What the server verifies is hashes. The event chain from hook capture is not re-checked there (run `miaudit verify` locally), and nothing proves who pushed: the author shown is what the manifest says.
- Query from the CLI (read-only, no token, works from any directory; server from `--server` or `MIAUDIT_SERVER`, and `MIAUDIT_READ_PASSWORD` when the server has a read password): `miaudit remote repos`, `miaudit remote audits owner/name [--author LOGIN] [--gap CODE_PREFIX] [--page N | --all]`, `miaudit remote show owner/name <audit_id>`. Without `--json` they print a table; with `--json` the usual envelope. `--gap` matches the start of a gap code, so `--gap CAPTURE_UNAVAILABLE` lists audits with no hook capture and `--gap FRONTEND_EVIDENCE_MISSING` lists audits missing screenshots. Gap codes are stored on each audit document at ingest and backfilled for older documents when the server starts.
- Tests: `cargo test --workspace` runs the server suites against a real MongoDB when `MIAUDIT_TEST_MONGO_URI` is set (each test uses its own database) and prints `SKIPPED` otherwise; `scripts/e2e.sh` has a server section under the same variable.

## What it does not do (still open in the docs)
No MCP server, trusted harness, full execution receipts (only command digests via hooks), `check`, `fetch`, `review`/`approve`, policy evaluation, signatures, user accounts or per-repository permissions. Local blobs are **not encrypted** and no retention policy is applied; the capture coverage table and gaps no longer list `local_encryption` or `developer_review_observation`, so this README and `CLAUDE.md` are the only places that say blobs are unencrypted and that no review or approval flow exists.

## Trust model implemented here
- Everything supplied by a caller is stored as `self_reported`; only hook events written through `miaudit capture` are `observed`. File snapshots are labeled `unverified_client_snapshot`: the CLI is not a trusted harness.
- An audit commit never claims approval or policy success. `accepted`, `verified`, `policy_passed` and `human_approved` are separate results.
- The manifest excludes its own ID, signatures, Git bindings and approvals; those are separate attestations.
- Snapshot scope is **staged paths only**; `.git/` and `.miaudit/` are excluded and gitignore is not consulted. All of this is recorded in the manifest.
- Single writer: no inter-process locking.
